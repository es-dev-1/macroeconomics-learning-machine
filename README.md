# Economics learning board

A learning machine: an AI tutor that teaches by asking questions and setting tasks, plus a study board that serves as its connected knowledge base. First course: Makroökonomik I. The board has four boards (Maths, Micro, Makro, Tutorium) with typeset formulas and graphs computed from the model equations. Maths and Micro are in English, Makro and Tutorium entirely in German.

## Use it
- **The board online:** https://es-dev-1.github.io/macroeconomics-learning-machine/ (GitHub Pages). A link with a section opens it in focus, for example `#macro/f-ma6` for the Solow model. Online the board is read-only: notes, moved cards, the tutor's pick, and the progress colors are saved only in the claude.ai artifact version.
- **The tutor:** copy `skill/learn/` to `.claude/skills/learn/` in the folder where you start Claude Code, place this course folder at `projects/<course>/` below it, and say "let's study". The tutor reads `data/course.md`, asks a short intake, and creates the learner files.
- **What is in this repository:** the board (`deliverables/`), the course data and the connections (`data/`), the design and planning documents (`docs/`), the tutor skill (`skill/learn/`), and the board model tests (`tests/`). The learner's own files and the faculty's material are kept out (see `.gitignore`).

## Goal
Main task (set by Elias on 2026-11-15, full text in `docs/2026-11-15-learning-machine-charter.md`): build a learning machine that lets a person learn any topic deeply and apply it when it counts. The learner mostly works in a Claude Code session, where the tutor (skill `learn`) asks questions, sets tasks, and builds up from single questions to mixed sets to timed practice exams modeled on the faculty's exams. The board is the knowledge base: it holds the knowledge, shows how it connects (macro to its micro and maths foundations), and should let the learner focus on what matters right now. Macroeconomics is the first test case: Elias wants to write his best exam. The design keeps method (skill), course (this folder), and learner (progress files) apart, so the same tool works for other topics later.

For the board itself: one section per course topic, with formulas typeset in the lecture's notation, graphs computed from the model equations, formula sheets, and self-test questions.

## Quick context
Elias stopped using Claude for economics because earlier versions drew graphs that were not mathematically accurate and could not reproduce formulas from screenshots as typeset math. This board is the test of whether that now works. The Micro board follows the Mikroökonomie I slides (Sommersemester 2025, 662 slides, in Downloads) and cites slide numbers. The Makro board follows the filled-in slides of Makroökonomik I (WiSe 2025/26, "VL XX ausgefüllte Folien.pdf" in `~/Downloads/MAKRO LECTURE SLIDES`; VL 15, 24, and 25 exist only as unfilled slide files there) and cites their footer numbers ("Folie 3.29").

## How it is built
- Single HTML file: `deliverables/macro-learning-board.html`, published as a private claude.ai artifact (URL below). The file is a page fragment (the artifact adds the document skeleton). For GitHub Pages, `index.html` fetches it and writes it into a full HTML document, so the online board is always the current file without a second copy; `.nojekyll` keeps GitHub from processing the files.
- Endless pan-and-zoom canvas: content cards grouped in topic frames, plus Elias's own notes and arrows. Design: `docs/2026-10-11-canvas-board-design.md`, plan: `docs/2026-10-11-canvas-board-plan.md`
- Formulas: MathJax 3 with SVG output (LaTeX source)
- Graphs: hand-written SVG, every point computed from the equations in the page script; nothing drawn freehand. All closed-form answers of the graphs were checked against brute-force numeric searches on 2026-11-11.
- Card id prefixes: `m` for the math toolkit (0.1 to 0.10, frames `f-m...`), `mi` for the micro lecture sections (frames `f-mi1` to `f-mi14`, questions `miq<section>-<n>` in `f-mi-quiz`), `macro-intro` for the Makro intro, `ma1` to `ma56` for the Makro sections (frames `f-ma1` to `f-ma56`, graphs `maN-graph-...`, formula sheets `ma-formeln-N` in `f-ma-formeln` to `f-ma-formeln5` (one per batch of lectures), questions `maqN-k` in `f-ma-quiz` to `f-ma-quiz5`), `tu` for the Tutorium board (frames `f-tu-intro`, `f-tu1` to `f-tu26`, `f-tu-extra` to `f-tu-extra5`; own extra tasks `tux-N` to `tux5-N`). Leitideen cards are `li-<idea id>` in frame `f-ma-leitideen`, generated by `board-links.py` between the markers `CONCEPT-CARDS-START frame=f-ma-leitideen` and `CONCEPT-CARDS-END` (never edit them by hand).
- The micro lecture cards were drafted from the slides by four subagents (every number checked against the slide images) and merged with `assemble.py` (kept in the session scratchpad, not in the project).
- The Makro and Tutorium content was drafted by six subagents (two for text, three for graphs, one for the Tutorium) and merged with `integrate_macro.py`; the VL 6 to 9 batch by six more subagents, merged with `integrate_macro2.py`; from VL 10 on, batches are merged with `integrate_batch.py` (latest version `integrate_batch_latest.py`, CONFIG for VL 20 to 26), which has a CONFIG block per batch and also merges the batch's connections into `data/knowledge-links.json` (all in the session scratchpad). Insertion markers in the page: `MACRO-SECTIONS-START/END`, `TUTORIUM-SECTIONS-START/END` (cards) and `MACRO-GRAPHS-JS-START/END` (graph scripts, registered in the shared `MICRO_GRAPHS` registry).
- Light theme only.
- Fonts: all text in Patrick Hand, loaded from Google Fonts as the face `Board Hand` with its own `unicode-range` that leaves out the digits (and the signs ², ³, ±, ×, ÷, −) and the space. Digits therefore fall back to the plain fonts in `--sans-plain` (Source Sans 3) and `--serif-plain` (STIX Two Text); leaving out the space keeps the plain fonts' line metrics and `ex` unit, so MathJax formulas keep their size. Graphs (`.chart`, `.gt-box`, `.legend`) and `.plain-math` use the plain fonts. `--sans` and `--serif` are the handwriting stacks; new CSS for text uses them, new CSS for numbers in graphs uses the plain ones. Layouts wait for the face to load (`handReady`, at most 4 seconds).
- Layout model (pure JS in `<script id="board-model">`) is unit-tested: `node --test tests/board-model.test.mjs` (needs Node.js, which is not installed on the Mac as of 2026-11-11)
- Saving: artifact `db` capability, one private document per viewer at `data/users/<id>/board` (`{v, layout, nodes, frames, notes, arrows}`); pan/zoom position stays in the browser only

## Boards
- The page has four boards, defined in `SPACES` in the page script: Maths (0.1 to 0.6, math sheet and self-test), Micro (overview, lecture sections 1 to 14, micro self-test, then the math tools 0.7 to 0.10 with their sheet and self-test), Makro (overview, sections 1 to 6.6, two formula sheets, two self-tests; German), and Tutorium (tasks 4.4.2 to 4.4.10, A29, 3.6.2, 7.6.1, 7.6.2, A30, 11.8.3, extra tasks; German). Boards with `de: true` get a German contents menu. Each board lists its frames in rows and is laid out from its own origin; only the current board is shown (the others get the `off-board` class).
- Switch with the top buttons, the keys 1 to 4, or the link hash `#maths`, `#micro`, `#macro`, `#tutorium`. A hash with a section (`#macro/f-ma6`) opens that section in focus mode.
- Focus mode: the Focus button on a section (or in the top bar, for the section in the middle of the screen) hides everything else on the board. The panel on the left shows the section's connections from `LINKS` (generated from `data/knowledge-links.json` by `board-links.py`, between the markers `KNOWLEDGE-LINKS-START` and `KNOWLEDGE-LINKS-END`). Escape or "Exit focus" leaves it. The last focus is remembered in the browser.
- Tutor pick: the board subscribes to `data/users/<id>/tutor` (`{section, note, cards, updated}`). A new `updated` value moves the focus there, unless the viewer is focused on something they chose; then a toast and the "Jetzt dran" pill offer it. Picked cards get a yellow ring. Each board remembers its own pan and zoom in the browser; the last board used is remembered too.
- Notes and frames you draw store their `board`; content cards and frames take their board from `SPACES`. Arrows live on the board of the item they start from. "Reset layout" resets only the current board.
- Saves carry `layout: 11` and are merged board by board (`mergeByBoard`). Older saves are converted once on load: layout 1 or 2 are split into boards by `migrateBoards`; below layout 11 `refreshBoards` lays out all four boards fresh (version 20 made every card with links taller, version 21 changed the font), but only boards that hold none of Elias's notes or frames. Boards with his items keep them, and new sections join on the right.
- Card links, knowledge network, Leitideen, progress: `buildCardLinks()` adds a `.card-links` row at the foot of every card that is an end of a labelled connection (built at startup from `LINKS`, before the first layout). The network overlay (`#net`, `openNet`) lays out the sections in the columns given by `PARTS`; `CONCEPTS` feed the Leitideen chips and threads. All three objects come from `data/knowledge-links.json` via `board-links.py`. The board subscribes to `data/users/<id>/progress` (`{sections: {id: {s, due}}, updated}`, statuses `started`, `known`, `understood`, `solid`, `ready`) and shows statuses in the network and the focus panel.

## Adding a new section
1. Add the content cards as `<article class="card" data-id="..." data-w="...">` blocks (header, body, resize handle) in the items layer. Card ids must stay stable forever, because saved layouts are keyed by them.
2. Add one entry per topic to `FRAMES` (id, number, title, card columns) and add its frame id to a row of the right board in `SPACES`.
3. Republish to the same URL. Saved layouts keep their arrangement; new frames appear to the right of the existing content on their board.

## Learning machine files
- `docs/2026-11-15-learning-machine-charter.md`: mission, teaching method, what the board must do, status, and roadmap.
- Skill `learn` in `ea-personal/.claude/skills/learn/` (copied to `skill/learn/` in this repository by the pre-commit hook in `.git/hooks/pre-commit`; edit the original): the tutor's method (`SKILL.md`), the course folder format (`references/course-folder.md`), and four scripts: `scripts/board-map.py` builds the knowledge map, `scripts/board-links.py` writes the connections, Leitideen, and network columns into the board, `scripts/board-section.py` prints one section or card as text so the tutor never has to load the whole board, and `scripts/board-path.py` prints how a section or Leitidee connects to the rest of the course.
- `data/course.md`: course facts, material, coverage. Exam date, format, and scope are still open.
- `data/knowledge-links.json`: the one place where connections are recorded: per section `builds_on` and `practices` (each with `what`, `how`, `here`, `there`) and `source`, plus `concepts` (the 21 Leitideen) and `parts` (the network columns). Extend it whenever sections are added to the board.
- `data/knowledge-map.md`: generated, never edited by hand. Rebuild after every board or links change: `python3 ../../.claude/skills/learn/scripts/board-map.py deliverables/macro-learning-board.html --links data/knowledge-links.json --out data/knowledge-map.md`, then `python3 ../../.claude/skills/learn/scripts/board-links.py deliverables/macro-learning-board.html data/knowledge-links.json` and republish the board
- `data/learner-profile.md` and `data/learner-progress.md`: Elias's goal, plan, and progress. Filled in by the tutor. Not in the git repository (`.gitignore`), so they stay private.
- `data/sources/` (lectures, tutorials, exams, prerequisites): the place for the course material. Still empty: the slides are in Downloads. Not in the git repository, like `data/exam-analysis.md` and `data/practice-exams/`.
